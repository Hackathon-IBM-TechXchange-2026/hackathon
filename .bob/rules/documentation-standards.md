# ChangeFlow Documentation Standards (Code-Coupled & Intent-Driven)

<instrucoes_exatas>
## 1. Code-Coupled Documentation Mandate
- **Synchronous Sync**: Any modification to method signatures, API endpoints, query parameters, request/response bodies, status codes, or database models must immediately and synchronously update corresponding documentation files (`sample-app/docs/API.md` and `sample-app/docs/ARCHITECTURE.md`).
- **No Orphaned Endpoints**: 100% of newly introduced or modified endpoints must contain complete parameter schemas, type constraints, default values, and response examples for `200/201`, `400`, `404`, and `422/500` status codes.
- **Architectural Traceability**: Whenever component relationships or sequence flows change, update the Mermaid sequence and class diagrams in `sample-app/docs/ARCHITECTURE.md`.
</instrucoes_exatas>

<documentacao_de_intencao>
## 2. Intent-Driven Documentation (Why vs. What)
- **Focus on the Business "Why"**: Documentation generated by AI agents must never merely paraphrase syntax (e.g. avoid *"This method adds a parameter"*). Instead, document the business justification and technical intent (e.g., *"Added PIX instant settlement rail to reduce transaction fee costs by 65% for Brazilian Real (BRL) operations and enforce O(1) fee caps"*).
- **Domain Constraints & Rationale**: Explicitly document security assumptions, rate limit considerations, and regulatory constraints (e.g., Central Bank of Brazil compliance for PIX transactions).
- **Markdown & OpenAPI Schema Compliance**: Markdown tables must be cleanly formatted and OpenAPI 3.1 JSON schemas must pass schema validation without loose typing.
</documentacao_de_intencao>
