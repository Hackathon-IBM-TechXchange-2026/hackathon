Context & Gap Analysis

What existsWhat's missing
Orchestrator has 5 inline agents (Analyzer, Reviewer, Documentation, Test Engineer, Validation) with regex-based static analysis and Jest-only test runner. Onboarding Agent (onboarding_agent.py) — stack detection, Mermaid diagrams, AGENTS.md generation, starter tasks — has no pipeline entry point.
Code Reviewer in orchestrator uses 7 simple regex rules applied to the diff only. Code Reviewer Agent (code_reviewer_agent.py) — richer rule set (SQL injection, PCI log exposure, empty except, file handle leak, function length), structured Finding objects, per-spec severity system — is isolated.
Test Engineer in orchestrator delegates to TestRunner (Jest / Node). No Python AST skeleton generation. Test Engineer Agent (test_engineer_agent.py) — AST-based PyTest skeleton generation, self-healing loop, coverage estimation — is isolated.

Design Rationale

DecisionWhy
Import-and-call, never copy bodies Follows the README's explicit split: .py = deterministic hands; .md = LLM persona. Avoids drift between agent module and orchestrator.
Onboarding as Agent 00 pre-flight The KB doc (§3) positions onboarding as a Day-1, pre-commit gate — it must run before any diff analysis so the AGENTS.md is fresh.
Code reviewer augments, not replaces Existing orchestrator reviewer produces a numeric score used by the validation gate. Replacing it would break run_validation_agent. Augmenting merges richer findings while keeping the score computation intact.
Self-healing loop is conditional on test file existence self_healing_loop requires a real test file path. The convention tests/test_<stem>.py is safe to skip if absent — it matches the agent spec's "stop if infra is missing" escape hatch.
Four-Part Contract structure Directly mirrors the KB doc §6 "binding contract" model (Objective / Limits / Format / Exit Strategy), ensuring idempotent, auditable results from Bob.
